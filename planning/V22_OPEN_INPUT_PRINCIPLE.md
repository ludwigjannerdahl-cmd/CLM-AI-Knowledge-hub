# V22 Open Input Principle

High-capability models should receive **tight truth constraints and open design space**.

## Tight

Be explicit about:

- source authority;
- semantic distinctions;
- factual prohibitions;
- reader questions;
- failure modes;
- acceptance criteria.

## Open

Do not pre-decide unless evidence requires it:

- diagram family;
- DOM hierarchy;
- component structure;
- illustration technique;
- interaction mechanism;
- spatial composition;
- visual density;
- implementation technology.

## Why

Overly prescriptive design instructions create path dependence: the model optimizes local compliance with the existing solution rather than searching the larger solution space.

Under-specified aesthetic prompts create the opposite problem: generic high-frequency patterns.

The target is therefore:

> constrain what must remain true; show what excellent feels like; leave the bridge open.

This principle applies to the golden-scene sprint and should be reconsidered before any future large prompt/skill bundle is added.
