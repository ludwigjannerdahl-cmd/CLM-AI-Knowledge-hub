# V22 semantic safety contract

Visual ambition must not silently strengthen claims.

The following distinctions remain non-negotiable while the visual system becomes more expressive:

- source-linked != verified;
- reviewed != approved;
- structured != executable;
- runtime available != interface available;
- interface available != permission granted;
- proposed != implemented;
- designed test != observed pass;
- prior-version evidence != evidence for a revised version;
- useful work product != reusable institutional context;
- visual prominence != importance, maturity or authority.

## Visual encodings

Depth may encode grouping/materiality only. It must not encode maturity.

Colour may encode a small number of explicit states. Every high-impact state has a text label.

Connectors use explicit relationship meaning where the relationship matters.

Source documents, interpreted requirements, implementation/test objects and evidence records remain visually distinct.

Unknown or missing evidence is shown as an absence/boundary, not replaced with generated metrics.

## Prototype wording

The V22 prototype uses generic or synthetic wording when Project evidence does not support stronger claims. Any move from prototype wording into production must bind to the existing V21 source model rather than copy the prototype text literally.
