## Outcome and purpose

The Hub now has one reading experience. The opening explains useful CLM work, selected context considered for reuse, and the effect of information/operating conditions before asking the reader to choose a detail. The first action names a source-of-wealth preparation task. Full authored Hub topics are embedded in relevant contexts and remain reachable directly through the shared topic navigation and search.

The organisational question is whether another colleague can use the context without Ludwig reconnecting it. No staffing comparison, inferred productivity multiple or automatic reuse benefit is used to make that argument.

## Narrative and composition decisions

The reference deck was inspected as design input. It supports the restrained green header, pale editorial surface, clear hierarchy, document specimens, contextual inspection and explicit states. It also contains invented article numbers, dates, current-state badges and metrics; none of those are evidence.

Three opening approaches were considered: a large spatial layer stack, an analytical inventory, and a work-centred editorial explanation. The latter was selected because it can state the contribution and review condition before a click without making the reader understand a taxonomy. The composition uses a requirement fragment and a versioned instruction folio, with explicit review annotations and a condition consequence. This choice has not yet been compared in a rendered or reader test.

The representative paths use different compositions:

| Reader question | Form |
| --- | --- |
| What does the source actually support? | Indexed source passage beside the task explanation; then an annotated preparation specimen |
| Why does context matter? | Inspectable client / related-party / legal-entity field structure |
| What should the system do? | Instruction, requirement acceptance logic, mapping and adverse test examples |
| What changes with a revision? | Version comparison, affected-object list, pinned historical evidence |
| What if a condition is missing? | Independent assumptions and graded route consequences |
| What is the authority or limitation? | Object/source reading with local metadata and contextual return |
| Where is the extensive explanation? | Full native topic blocks, tables, nested topic controls, expandable text and citations |

No copied enterprise screen, decorative AI illustration or new dashboard metric is used. Precise meaning stays in HTML and controlled SVG. Mobile CSS reprojects the specimen relationships into a reading sequence rather than scaling a wide canvas down. Motion is nonessential.

## Engineering decisions

Dependency-free browser application with HTML, CSS and JavaScript. Reusable view functions, an explicit model layer, canonical object IDs, a source registry, and a separate advisory scoping engine. Browser-local notes and history are intentionally not institutional records.

The static build has no model service, live Mentor runtime, API integration, analytics, account system or external runtime dependency. It works from a folder or a repository subpath. Source files generate both a modular entry point and a self-contained HTML entry point.

The old HTML is parsed as content, never run as another application. Retired scripts, captured personal scope history and analytics are excluded. The full Mentor builder packet remains excluded from distributable assets. Relevant reported findings are qualified in the native explanation.
