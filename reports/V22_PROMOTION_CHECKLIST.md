# V22 promotion checklist

Do not migrate the prototype into production until all of the following are true.

## Visual acceptance
- Overview has one clear focal composition and does not collapse into equal cards.
- Develop CLM makes source, requirement, adverse test and missing result materially distinct.
- Govern/change keeps prior evidence pinned to its original version/scope.
- Knowledge transformation visibly distinguishes readable, structured and actually consumed context.
- Conditions visually change only the affected route when a scenario condition changes.
- Evidence shows record -> evaluation -> candidate change without automatic learning implication.

## Semantic acceptance
- No source-linked -> verified implication.
- No reviewed -> approved implication.
- No structured -> executable implication.
- No interface -> permission implication.
- No proposed -> implemented implication.
- No designed test -> observed pass implication.
- Unknown ownership/readiness remains unknown.

## Engineering acceptance
- Production migration uses shared runtime components, not a parallel static fork.
- `src/` remains authored and `docs/` generated.
- Existing V21 model/controller/source-preservation tests pass.
- Existing Chromium regression/interactions pass.
- New visual-comparison screenshots are retained for the accepted production surfaces.
- Responsive semantics hold at desktop/tablet/mobile.

## Reader acceptance
- An unfamiliar colleague can explain the work-first model.
- They can distinguish source, interpretation, requirement, implementation/test and evidence.
- They can explain why a missing interface changes one route but not supplied-document preparation.
- They can explain why prior evidence cannot simply move to a changed version.

Reader misunderstanding remains evidence for revision rather than a score to average away.
