# V22 reference families

The supplied visual boards are used as **visual-only** comparators. Generated copy, numbers, statuses and enterprise claims are not adopted.

## Family A — Work-centred orientation

Use for Overview and broad system orientation.

Strong reference qualities:
- one dominant explanatory composition rather than many equal cards;
- asymmetric hero layout with generous negative space;
- layered/contextual depth around recognisable work;
- restrained annotations and connectors;
- clear human judgement and operating-condition boundary;
- deep green used as focal material rather than background everywhere.

Avoid copying:
- invented evidence counts/freshness;
- model/agent-centric centrality where work should be central;
- serif typography or photographic assets as if brand-approved.

## Family B — Source / requirement / test

Use for Develop CLM.

Strong reference qualities:
- literal source sheet with highlighted passage;
- materially distinct interpretation/requirement sheet;
- compact provenance rail;
- annotations adjacent to the object they qualify;
- enough whitespace for the reader to compare source and interpretation.

V22 extension:
- adverse test is a distinct margin object;
- missing implementation/result is visible absence;
- human responsibility cuts across the trace.

## Family C — Version / change / impact

Use for Govern/change.

Strong reference qualities:
- aligned version comparison;
- selective change markers rather than complete re-rendering;
- impacted objects grouped by dependency;
- evidence and uncertainty visually separate from the proposed change.

V22 extension:
- old evidence remains visibly pinned to the old version;
- propagation is interrupted where derivation/evidence is not established;
- the human decision appears as a next decision, not as a status baked into geometry.

## Family D — Knowledge transformation

Use for Knowledge & methods.

Strong reference qualities:
- source material visibly transforms into structured objects;
- structured object has inspectable identity and relationships;
- only selected context crosses into bounded task consumption;
- object detail becomes denser without changing visual language.

## Family E — Operating conditions

Use for Data & operation.

Strong reference qualities:
- condition routes visibly change when a condition is absent;
- supplied-document and live-data routes remain independent;
- permission / record change is not conflated with technical reachability;
- status uses small semantic treatments rather than large decorative banners.

## Family F — Evidence / evaluation

Use for Evidence and observability.

Strong reference qualities:
- record before interpretation;
- scope/version visible near the record;
- evaluation as an inspectable process, not a generic “green” conclusion;
- candidate change separated from observed evidence.

## Family G — Reference / inspection

Use for object detail, source reading, typed relationships and search.

Strong reference qualities:
- denser product-reading mode;
- persistent context rail;
- direct source-return path;
- one-hop relationship context rather than force-directed complexity;
- efficient search result scanning with object type/status/source visible.

## Use in review

The visual-comparison process should compare by family, not attempt to match one screenshot pixel-for-pixel. Each production surface should inherit the relevant family grammar while preserving V21 semantic contracts.
